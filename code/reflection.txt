The biggest thing I learned in this assignment is that a Streamlit script doesn't behave like a normal Python program. It doesn't run once and wait for input. It reruns from the top every time the user interacts with the page, whether that's typing a character, choosing a file, or clicking a button. Coming from console apps in Assignment 02, that took some getting used to. In one_package.py this showed up as the need for a guard: if package_data: had to wrap everything below the text box, because on the very first run, before anyone types anything, st.text_input returns an empty string, not None and not an error. Without the guard, the app tries to parse "" and crashes.
process_file.py reinforced the idea that widgets are just function calls that return a value. st.file_uploader returns None until a file is chosen, and once it returns something, that something is bytes, not text. I had to call .getvalue().decode("utf-8") before splitting it into lines. I also had to account for the trailing-newline problem: splitting a file's text on line breaks leaves an empty "line" at the end, and parse_packaging raises a ValueError on an empty string, so I made sure to strip and skip blank lines wherever they showed up, not just at the end.
process_files.py is where the rerun model actually mattered instead of just being a fact I'd read. I made a point of not keeping the running total in a plain variable, since a rerun would reset it to zero every time; it can't survive between uploads. Instead I initialized st.session_state once, with if "files_processed" not in st.session_state:, and only updated it in response to an action. The second trap was that the uploader keeps holding onto the chosen file across reruns, so I made sure processing only happened behind st.button("Process file", key="process"), which is True only on the one rerun the click caused. Otherwise choosing a file without clicking would silently recount it on the next unrelated rerun.
If I were doing this again, I'd write the session-state initialization and the button guard first in process_files.py, before any of the parsing logic. Most of my debugging time there went into figuring out when state was being updated, not into the parsing itself.
